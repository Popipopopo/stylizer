# 观测箱 · Stylizer

一个纯前端的图像风格化工具，两种模式：**色块化**（把照片压成一张平涂的限色插画）和**像素 / 抖动**（低分辨率 + dither 的复古像素感）。上传一张图 → 拉滑杆 → 实时预览 → 导出 PNG。全程在浏览器本地跑，不上传任何图片，无第三方依赖。

A client-side image stylizer with two modes: **color-block** (Kuwahara smoothing + OKLab palette quantization + region cleanup, turning a photo into a flat limited-palette illustration) and **pixel/dither** (downscale + ordered/error-diffusion dithering). Everything runs locally — no uploads, no dependencies, no build step.

## 直接用

在线版：**https://popipopopo.github.io/stylizer/**

也可以把 `index.html` 下载到本地，用浏览器直接打开，功能完全一样。

## 色块化

把照片变成参考图那种「大块纯色 + 干净边界」的插画感。管线是：

```
箱式降采样 → 调色（含彩度）→ 提取色卡 → Kuwahara 抹平 → 量化 → 形状清理 → 质感
```

几个滑杆的作用：

- **抹平（Kuwahara）** —— 每个像素看周围四个重叠方窗，取方差最小那个的均值。区域内部被抹平，边界不糊反而更锐。用积分图实现，所以半径拉到 10 也不会变慢。
- **色相分离** —— 最值得玩的一条。它决定电脑在挑色卡时，是按「什么颜色」分家，还是按「多亮多暗」分家。
  照片的明暗差异通常远大于色相差异，不加权的话你会得到**同一个土色的 N 个深浅**（这就是"颜色不丰富"的由来）；把这条拉高，不同的色相才会各自拿到名额。
- **最小色块 / 清理** —— 把碎屑并进相邻的大色块。「像人画的」和「像滤镜跑的」，区别很大程度上就在这一步。
- **色块噪动** —— 只作用在色块**内部**，边界像素不动，所以轮廓始终干净。

色卡可以自动提取（OKLab 空间的 k-means++），也可以点「← 收下自动色卡」把它变成可手动编辑的色卡再微调。

### 从图取色

两个按钮，两种来源：

- **从当前图取色** —— 直接用你正在处理的这张图吸一套色卡。走图自己的颜色，所以映射方式用「最近色」（和「自动提取」一个道理，保得住画面本来的颜色关系）。
- **从参考图取色** —— 另传一张图，只借它的颜色（下面详述）。

#### 从参考图取色

「从参考图取色」可以传任意一张图，只借它的颜色：电影截图、画作、老游戏截图都行。

- **如果参考图本身颜色就少**（比如 16 色的 EGA 游戏截图），会**原样照抄**那几个颜色，不做任何近似。所以想要某套硬件调色板，丢一张那个年代的截图进去就有了，不需要谁去硬编码 EGA / CGA / C64 的色值。
- **如果是连续调的照片或画作**，走 k-means 聚类，色数听「色数」滑杆的。

配套的「映射方式」很关键，因为**偷色卡 ≠ 偷风格**：

| 方式 | 做法 | 什么时候用 |
|---|---|---|
| **按最近色** | 每个像素找感知上最接近的颜色 | 用自动提取的色卡时。保得住画面本来的颜色关系 |
| **按明暗排序** | 色卡按明度排队，原图明暗也切成同样多档对上去（相当于渐变映射） | 套用别人的色卡时。**强制用满整套颜色** |

差别有多大：拿一张偏亮的图去套一套偏暗的 8 色色卡，按最近色只会用到其中 **2 个**（全挤在亮端，暗色一个用不上，完全不像参考图）；按明暗排序会用到 **7 个**，整套色卡都进画面。所以从参考图取色之后会自动切到「按明暗排序」。

## 像素 / 抖动

- 降分辨率、亮度 / 对比度 / 冷暖 / 彩度
- 抖动：无 / Bayer 4×4 / Bayer 8×8 / Floyd–Steinberg / Atkinson
- 色卡量化、双色调、胶片颗粒、色差

> **按高度定尺寸**：像素模式的工作分辨率锁的是**高度**（像素块=2 时高 415，宽度随原图比例走），
> 而不是长边。这样 **2× 导出的高度恒为 830**，正好填满游戏里 824 高的背景框——不管原图是宽是窄，
> 每个房间导出的高度都一致、都填满，Godot 里 1:1 直接用，不需要拉伸，像素大小也就统一了。
> 宽度无所谓：比框宽就在游戏里左右滚。

### 修补（画笔涂抹）

觉得某块区域杂点太多、想手动刷成一片平色？勾上「画笔涂抹」：

1. 点「吸管」，在画面上点一下，取那个位置的颜色当填充色（也能点色块手动选）
2. 按住在杂点上刷，刷过的地方变成那一个纯色

关键在于**涂抹是盖在整条管线的最后一步**：它存成一串归一化坐标的笔画，每次重算都重新盖上去。所以涂完之后你照样能拉任何滑杆调整，涂抹不会被冲掉；导出也自动带上。

- 每刷一笔算一步撤销
- 坐标是归一化的，改「像素块」分辨率也不跑偏
- 涂抹绑定当前这张图，换图会自动清空（所以它不进「命名预设」——预设是要跨图复用的）

## 通用

- **撤销 / 重做**：`Ctrl/⌘ + Z` 撤销，`Ctrl/⌘ + Shift + Z`（或 `Ctrl + Y`）重做。拖一次滑杆算一步，不会被拆成几十步
- **预设**：每种模式都有内置几套；也能把当前设置存成命名预设。自动记住上次的设置
- **导出 PNG**：Chrome / Edge 里会弹出系统保存对话框，可以自己挑文件夹；Firefox / Safari 没有这个 API，自动退回直接下载
  导出用的就是预览那一张——同一份像素，**所见即所得**
- **导出倍数**（1× / 2× / 3× / 4× / 6× / 8×，学 Figma）：**只放大文件，不改变画面内容**。
  用最近邻放大，每个格子变成一个实心方块，不产生任何过渡色——所以 2× 导出的颜色数和 1× 完全一样。
  文件名会带 `@2x` 后缀。每边上限 8192px，超了会自动夹到能用的最大整数倍
- **画布缩放**：右下角 `−／＋`，或 `Ctrl/⌘ + 滚轮`（朝鼠标位置放大）。只影响预览显示，不改导出。放大后拖动画布浏览
- **导出历史**：每次成功导出会自动记一条——**当时的全部设置 + 一张缩略图 + 时间/文件名/尺寸**。点「导出历史…」打开画廊，**直接点任意一张缩略图**就把旋钮拨回那次导出的样子（连修补涂抹也存）；右上角 `×` 删除单条。
  为省空间**只存设置和缩略图，不存原图**——想完整复现就重新打开当时那张原图，再点恢复。记录存在浏览器本地（换浏览器/清缓存会没），只留最近 40 条

### 导进游戏引擎发现糊？

多半不是图的问题，是引擎在做双线性插值。先去把**纹理过滤改成 Nearest / Point**，再关掉 **Mipmap**，并确认贴图压缩是**无损**而不是 VRAM 压缩——BC/DXT 压缩会在硬边界附近产生色渗，还会把你限出来的那几个颜色炸成几百个。

改完之后如果只是嫌"格子太粗"，那才是分辨率不够，这时候用导出倍数或调高工作分辨率。顺序反了的话，你会导出一张 4 倍大的图，发现还是糊。

## 技术

单文件 HTML + Canvas 2D + 原生 JavaScript，**无构建步骤、无外部库**。

图像算法放在 `<script id="algo" type="javascript/worker">` 里，运行时取出源码转成 Blob URL 起一个 Web Worker，所以拖滑杆时主线程不会卡。Worker 起不来的环境（某些浏览器的 `file://` 限制）会自动退回主线程执行，功能不变。

两个值得一提的实现细节：

- **渲染调度有背压。** Worker 忙的时候不再发新请求，只把最新一条压在待发位。否则拖一次滑杆会灌进几十条请求，Worker 一条条老实跑完，预览就会越拖越滞后。实测 40 次连续请求只会实发 2 条。
- **保存对话框在点击手势里立刻发起。** 先去算图再弹窗的话，用户手势已经过期，浏览器会拒绝，然后静默退化成普通下载——文件夹就再也选不了了。

所有效果都是逐像素的纯函数，想加新效果照着现有函数写一个，再挂进管线即可。

## 部署到 GitHub Pages

1. 新建一个仓库，把 `index.html`（和这个 README）放进去
2. 仓库 **Settings → Pages**
3. Source 选 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`，保存
4. 等一两分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`（本仓库即 https://popipopopo.github.io/stylizer/ ）

因为文件叫 `index.html` 且在根目录，这个链接会直接打开工具。
